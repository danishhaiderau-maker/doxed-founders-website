## Summary

Surfaces `relay_push` health and `ddollar_gate` state in `/api/relay-execution-state` so audit dashboards reading only the lightweight money-path snapshot can confirm:
- relay delivery health (`relay_push.last_ok`, `recent_deliveries_count`)
- DDollar entry-gate state (`ddollar_gate.passed`, `balance`, `minimum`)

## Root cause this fixes

A prior verification worker reported `relay_push.last_ok` and `ddollar_gate.passed` as MISSING from `/api/relay-execution-state`, with suspicion that ChatGPT had fabricated the fields. **They are not fabricated.** Confirmed live on the Fly bot:

```
/api/relay-state → state_integrity.relay_push.last_ok = true
                  state_integrity.bitfinex_live.ddollar_gate.passed = true (balance 17030 ≥ min 2000)
```

The fields existed only on the richer `/api/relay-state` endpoint. The lightweight `/api/relay-execution-state` snapshot did not mirror them, which led to false "missing field" reports. This is a real observability gap, not a hallucination.

## Change is pure read-only telemetry

In `_build_relay_execution_state_snapshot`:
- Reads `_relay_push_state` (module-level tracker) and counts `_relay_delivery_history_snapshot()` entries
- Calls `bitfinex_live_executor.ddollar_gate_status()` — the same function the live entry path consults, so the slim snapshot can never disagree with the authoritative gate
- Never places orders, never mutates state, never weakens any safety contract

The DDollar summary is never hard-coded — it always comes from `ddollar_gate_status()`. A future refactor that inlined `passed: True` to silence a noisy audit would now fail the new contract test.

## Tests

Adds `test_relay_execution_state_telemetry.py` — source-level AST contract checks that lock:
1. `state_integrity` surfaces a `"relay_push"` block reading from `_relay_push_state` (incl. `last_ok`) and `_relay_delivery_history_snapshot`
2. `state_integrity` surfaces a `"ddollar_gate"` block calling `ddollar_gate_status()`
3. The builder is read-only (no assignment into `_relay_push_state`, no `_record_relay_delivery` calls, no `_relay_push_history.append`)
4. The DDollar summary never hard-codes a `passed: True/False` boolean

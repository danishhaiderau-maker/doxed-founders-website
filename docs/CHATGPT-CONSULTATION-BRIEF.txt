WHAT WE UNDERSTOOD — YOUR REFINED VISION
----------------------------------------

INVERTED STACK (TRUST FIRST, NOT LAUNCH FIRST)

The product stack flows in this order:

  Community → Trust → Founder OS → Raise Room → Launch Qualification → Token Infrastructure → Liquidity → Trading

We reject launch-first and Pump.fun-style anon deploy. Founders earn graduation. We compete with Product Hunt, GitHub, AngelList, Kickstarter, and YC — not meme coin factories.

RAISE ROOM IS A MANDATORY PATH

Every project follows:

  Founder → List Project → Trust Review → Community Validation → Raise Room → Launch Qualification → Launch

Nobody launches immediately. Eligibility is earned.

PROJECT MATURITY STAGES

  IDEA → BUILDING → VALIDATED → COMMUNITY → READY → LAUNCHING → TRADING → GROWING

These drive UX badges and discovery filters. We map from legacy database lifecycle enums until migration.

RENAME: TOKEN LAUNCH → FOUNDER GRADUATION

Graduation is an achievement when launch qualification gates pass. A composite Founder Score (Builder + Trust + Community + Scout + Build + Delivery) displays at unlock. It is not a one-click mint.

DDOLLAR REFRAME: PROOF OF CONTRIBUTION

DDollar is earned via reviews, scouting, building, and validation — not only spent. Paper Raise Room uses simulated dollars; real economic effect waits for counsel-gated phases.

COMMUNITY ALLOCATION BUCKETS (WEIGHTED, NOT EQUAL)

  Validators .............. 25%
  Scouts .................. 20%
  Builders ................ 20%
  Early Followers ......... 15%
  Paper Raise ............. 10%
  Bug Hunters ............. 10%

We reject equal 10% airdrops to all active users (supersedes old TOKEN-LAUNCH-TRADING-ECOSYSTEM-PROPOSAL equal-split section).

LAUNCH QUALIFICATION GATES (EXAMPLE THRESHOLDS)

  Min project followers ............... ≥ 25
  Paper conviction .................... ≥ $10,000 simulated
  Community validation score .......... ≥ 70% weighted
  AI / scam pass ...................... No active investigation
  Identity ............................ X linked OR verified email + wallet
  Founder Launch Score ................ ≥ 65 composite

FOUNDER EXCHANGE (NOT "DOXXED DEX")

Only graduated projects list. Trust metadata visible. Jupiter-routed swaps in Phase 3 with tier-based platform fees.

REGULATORY ENGINE

Founder questionnaire classifies: Community Project | Utility Token | Governance Token | Capital Raise | Restricted. Features gate per class. Capital Raise path requires consult AU counsel — we will not ship real raises without that.

AUSTRALIAN LEGAL SEPARATION (ENGINEERING FRAMING, NOT LEGAL ADVICE)

  Company ........... community / software platform
  Blockchain ........ settlement for user-initiated transactions
  Users ............. self-custody wallets; no platform custody in Phase 1–3

1. MANDATORY PIPELINE UX: Should Launch Qualification gates be visible to scouts on project pages before founders pass them (transparency vs. gaming)?

2. FOUNDER GRADUATION NAMING: Is "Founder Graduation" clear to non-crypto founders, or should we pair it with a subtitle like "allocation registration unlock"?

5. PROOF OF CONTRIBUTION: Should spending DDollar on Raise Room escrow reduce reputation score or use a separate "committed" balance?

6. WEIGHTED BUCKETS: Validators 25% vs Paper Raise 10% — does this under-weight capital conviction vs. "would you pay" signals?

7. FOUNDER EXCHANGE LISTING: Should non-graduated projects appear in Discover with "not yet graduated" badge, or hide from trading-adjacent surfaces?

8. AUSTRALIAN FRAMING (PHASE 1 PAPER ONLY): Is "allocation registration" + "simulated paper conviction" sufficient distance from CSF / managed investment scheme language?

9. COMPETITIVE POSITIONING: Citing Product Hunt / AngelList — any risk when Raise Room shows dollar-denominated paper totals?

10. PHASE ORDERING: Regulatory Engine before any public token metadata preview — agree?

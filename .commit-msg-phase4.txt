Phase 4: agentic chat — tool use, Memory Engine injection, execution profiles, DDollar display

Add the Phase 4 agentic layer to the Founder IDE VS Code extension and wire
the server-side Memory Engine context endpoint.

Extension (packages/founder-ide-extension):
- Tool use (§4.3/§8.4): register founder.editFile, founder.runCommand, and
  founder.readWorkspace via vscode.lm.registerTool. editFile applies edits
  through vscode.workspace.applyEdit; runCommand creates a terminal and
  captures combined stdout/stderr to a temp file (the documented workaround
  for the limited terminal-read API); readWorkspace walks the file tree
  (respecting node_modules/.git/etc.) and optionally inlines file contents.
  All three are contributed via package.json languageModelTools with JSON
  schemas and can be referenced in chat with #editFile / #runCommand /
  #readWorkspace.
- Memory Engine injection (§8.3): new memory.ts fetches
  GET /api/memory/context?projectId=<workspace> (founder-node bearer, 4s
  timeout) and builds a system-prompt prefix from project + founder memory.
  chat-provider prepends it before each gateway call; graceful no-op on
  404/empty/error so chat never breaks.
- Execution-profile UI: new profile-manager.ts surfaces Turbo / Balanced /
  Architect / Autonomous as a QuickPick + status-bar item, persisted in
  workspace state, mapping each profile to a model alias / X-Execution-Profile.
- DDollar cost display: new cost-tracker.ts accumulates per-request DDollar
  spend from the founderOs SSE metadata line and shows a running session total
  in the status bar with a markdown tooltip table of recent requests.
- Chat participant: @Founder OS now drives a real vscode.lm round-trip —
  selects the profile's model, injects Memory Engine context, passes the
  founder.* tools, and runs the tool-call/tool-result agent loop (max 6
  rounds). /code forces the coding alias.
- extension.ts wires the tools, profile manager, cost tracker, and enhanced
  participant; adds founderOs.selectProfile / showCostBreakdown / resetCost
  commands. package.json bumps to 0.1.0 and declares the three tools.

Server (apps/api/src/memory-engine):
- New memory-engine.controller.ts exposes GET /api/memory/context
  (FounderNode-guarded) returning project + founder memory for the caller.
  The store backends are still stubbed, so it returns empty arrays
  gracefully — the plumbing is in place so the extension benefits
  automatically once real backends land in Phases 2-4.
- memory-engine.module.ts registers the controller.

No Prisma schema changes. No bot.py or sync-script changes.
